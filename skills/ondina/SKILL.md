# PR を ondina で開く

ondina は PR を解析し（`ondina analyze`）、ブラウザの画面で見せる（`ondina serve`）。レビュアーはこの画面で PR をざっくり理解し、そのあとでレビューコメントを頼む（スキル `ondina-comments`）。

## やらないこと

- 開く・見せると頼まれていなければ使わない。「ondina にコメントして」だけなら開かない（コメントはスキル `ondina-comments`。開いていなければ、あちらが「先に開いて」と返す）
- レビューやコメントはしない（同じ依頼で頼まれたときだけ、最後に `ondina-comments` へ進む）
- `ondina serve` を `--background` 無しで打たない。終わらないうえ、あなたが終わると画面も止まる
- リポジトリを別の場所に複製して解析しない。解析は対象のリポジトリの `.ondina/` に残す（`ondina-comments` とレビュアーがそこを読む）。worktree の中で打ってよい。PR の解析は、元のフォルダ（`.git` があるフォルダ）の `.ondina/` に入る
- あなたが作った PR の無い変更を見せるよう頼まれたとき（「作った変更を ondina で見せて」など）は使わない。スキル `ondina-preview` に進む

## 手順

コマンドは対象のリポジトリの中で打つ。

### 1. 何を開くか決める

- PR 番号: key は PR 番号。今の head は `gh pr view <番号> --json headRefOid --jq .headRefOid`
- 2 つのブランチ・コミット（「main と feature/x」など）: key は `local`。今の head は `git rev-parse <head 側>`
- どちらも言われていない（「ondina で開いて」「この PR を開いて」など）: 今いるブランチの PR を開く。番号を付けずに打つと、今のブランチ（worktree ならその worktree のブランチ）の PR が返る

  ```sh
  gh pr view --json number,title,state,headRefOid
  ```

  - `number` を PR 番号として、上の「PR 番号」と同じに進む。今の head は `headRefOid`
  - `no pull requests found for branch "<ブランチ>"` と出たら、このブランチに PR は無い。何も開かずに止まり、「このブランチ（<ブランチ>）の PR が見つかりません。開く PR の番号を教えてください」と伝える。main との差分などを代わりに開かない
  - ほかのエラー（ブランチにいない・gh の認証切れなど）でも、出力をそのまま伝えて止まり、PR の番号を聞く
  - `state` が `MERGED` か `CLOSED` でも開く（開いている PR が無いと、マージ済みや閉じた PR が返る）。手順 4 で、マージ済み・閉じていることを添える

### 2. 解析する（今の head の解析が無いときだけ）

```sh
ondina list
```

1 行が 1 つの解析で `<key> <headSha> <baseSha> <題>`（タブ区切り）。key の行に手順 1 の head があれば、解析せずに手順 3 へ。

無ければ解析する:

```sh
ondina analyze <PR番号>
ondina analyze --base <base 側> --head <head 側>   # 2 つのブランチ・コミット
```

- 数分かかる（LLM と言語サーバー）。終わるまで待つ。コマンドの待ち時間に上限を付けられるなら 15 分以上にする（途中で切ると解析が残らない）
- 最後の行が `.ondina/<key>/<headSha>.json` のパスなら成功
- 失敗したら、出力の最後の数行をそのままレビュアーに伝えて止まる（gh の認証切れ、言語サーバーの期限切れなど。直し方は出力に出る）

### 3. 画面を立てる

```sh
ondina serve --background <key>
```

`ondina serve: <URL>` の 1 行が出てすぐ戻る。このリポジトリの画面が既に動いていれば（別の worktree で立てた画面も）、新しく立てずにその URL を出す。その URL を手順 4 で開けば、今解析した PR がその画面に出る。止めるときは URL のポートを使う（下の「画面を止めてと言われたら」）。

標準エラーに「空いているポートで起動しました」と出ても失敗ではない（4177 番を別のリポジトリが使っていた）。出た URL を開く。

### 4. 開いて伝える

```sh
open "<URL>"
```

開けなくてもよい（URL を伝えれば足りる）。レビュアーに URL を伝え（番号を言われずに選んだときは、どの PR か番号と題も）、「画面で PR をざっくり見てから、コメントが要れば『ondina にコメントして』と頼んでください」と添える。

同じ依頼でレビューコメントも頼まれていれば（「開いてコメントして」など）、続けてスキル `ondina-comments` の手順に進む。

## 権限で失敗したとき

`Operation not permitted` や `EPERM` で失敗したら（サンドボックスで `.git` に書けない・ポートを開けないなど）、権限を上げて同じコマンドを打ち直す（許可を求める）。上げられなければ、打つコマンドをレビュアーに渡して止まる。

## 画面を止めてと言われたら

`ondina serve stop <ポート>`。ポートは手順 3 で出た URL のもの（4177 番が埋まっていたときは別のポートで立っている）。分からなければ `ondina serve list` で動いている画面（ポートとフォルダ）を一覧にし、このリポジトリのフォルダ（別の worktree のこともある）の行のポートを使う。
